# Open Engineering Images

The visual language of Open Engineering.

![Open Engineering Images hero-banner.png](../assets/hero-banner.png)

Open Engineering Images is the visual layer of the Open Engineering ecosystem.

We create, curate, transform and organise images that represent Open Engineering Elements — from physical prototypes and technical components to characters, products, architectures and worlds.

Make engineering visible.

⸻

## What is an Open Engineering Image?

An Open Engineering Image is more than a picture.

It is a visual representation of an Open Engineering Element, connected to its identity, provenance and context.

Open Engineering Element
          │
          ▼
    Visual Representation
          │
          ├── Reference
          ├── Technical
          ├── Product
          ├── Character
          ├── Environmental
          └── Cinematic

Images can therefore become reusable engineering assets rather than disposable illustrations.

Our Mission

Open Engineering Images aims to make engineering:

* visible
* understandable
* recognisable
* shareable

We combine photography, illustration, visualisation and generative AI to create a growing visual library for Open Engineering.

From Reality to Representation

A physical object can become a digital visual asset:

Physical Element
      ↓
Reference Image
      ↓
Visual Processing
      ↓
Generated / Enhanced Image
      ↓
Approved Visual Asset
      ↓
Open Engineering Library

The original reference remains part of the asset’s provenance.

Generated imagery does not replace reality — it provides another representation of it.

⸻

Visual Asset Types

Open Engineering Images can contain many kinds of visual assets.

Reference Images

Faithful representations of real objects and Elements.

Technical Images

Diagrams, schematics, architecture visualisations and engineering illustrations.

Product Images

Professional representations of physical products and prototypes.

Character Images

Visual representations of Open Engineering characters such as the PixStars.

Environmental Images

Places, scenes and contexts in which Elements exist.

Cinematic Images

Images intended for stories, performances, films and other visual experiences.

⸻

AI-Powered Image Generation

Open Engineering Images is designed to work with specialised visual AI capabilities.

Rather than making the ecosystem dependent on one provider, capabilities are modelled independently from their implementations.

For example:

Product Photography
        │
        ├── Monoshoot
        └── Other Providers
Image Generation
        │
        ├── Provider A
        ├── Provider B
        └── Provider C
Image Enhancement
        │
        └── Provider ...

This keeps the Open Engineering architecture provider-neutral.

⸻

Provenance Matters

An image should be understandable in context.

Where possible, Open Engineering Images maintains relationships between:

Element
  │
  ├── Reference Image
  │
  ├── Generated Image
  │
  ├── Transformation
  │
  └── Published Asset

This allows us to answer:

Where did this image come from?

and:

What does this image represent?

Images can move between these domains.

A photograph of a physical Element can become a product image.

A product image can become a character prop.

A character image can become a cinematic frame.

A collection of frames can become a Motion Picture.

Our Principles

Element-oriented

Images represent identifiable Elements rather than existing in isolation.

Reusable

Visual assets should be reusable across projects, applications and experiences.

Traceable

Images should retain meaningful provenance whenever possible.

Composable

Images should be usable as building blocks for larger visual compositions.

Provider-neutral

External image services are capabilities, not architectural dependencies.

Open

The ecosystem should favour interoperable formats, documented conventions and reusable assets.

Beautiful

Engineering does not have to look boring.
